# FoLocal 个人维护分支

本仓库基于 `Guyungy/Folo-Local`，该项目基于 `RSSNext/Folo`。两个上游都保留在 Git 历史中。

## 本地版修复

- 使用 `is.folocal.local` 应用标识和 `folocal://` 协议，不抢占原版的链接。
- 正式版数据保存在 `FoLocal`，开发版保存在 `FoLocal(dev)`。不自动读取原版 `Folo` 目录。
- RSS 图标地址支持相对路径和空白清理；网站图标直接访问源站，失败时有离线占位。
- 桌面窗口提供随主题变化的侧栏背景，避免透明区域出现黑底、图标不可辨认。
- 保留上游本地 SQLite、RSSHub 和 OpenAI-compatible 接口功能。

## 迁移与个人配置

迁移前退出应用，备份原版及 FoLocal 的完整数据目录。通过已有 `apps/server` 数据库导入工具，从明确指定的数据库副本迁移；不要让两个应用共用目录。

AI 配置由用户在本机填写。仓库不包含订阅数据库、OPML、浏览器 Cookie、账号、API Key 或个人 AI 配置。使用本地代理时，应保持代理运行。

## 两个上游如何同步

`upstreams.json` 定义两个来源。脚本只拉取远端引用、统计待同步提交并模拟合并检查冲突，不改变当前分支或工作文件，不推送代码，不创建 PR：

```bash
# 检查待同步提交和冲突
node scripts/upstream-sync.mjs

# 只检查一个上游
node scripts/upstream-sync.mjs --upstream=folocal
node scripts/upstream-sync.mjs --upstream=folo
```

这是个人自用分支，不使用 PR 流程，也不向两个上游提交 PR。更新需在隔离的工作区验证兼容性；通过后直接提交到自己的仓库。`FoLocal Checks` 在推送时验证类型、lint、服务测试、隔离测试和 Electron 构建。存在冲突时报告冲突，等待处理；没有文本冲突也不代表功能兼容。

官方 Folo 可能新增官方服务依赖、套餐判断或数据库变化，需要检查本地实现是否兼容。客户端自动下载安装更新暂未启用，避免覆盖本地数据和修复。

上游定时检查已取消；需要同步时手动执行上述脚本。继承的发布、部署等工作流已停用，仅启用自己的 `FoLocal Checks`。推送时运行代码检查，不检查上游更新。

## GitHub 手动打包

在本仓库 Actions → FoLocal Checks → Run workflow 选择 `dev`，保留 `package` 勾选。类型检查、lint、测试和构建通过后，使用 GitHub 的 macOS Apple Silicon 机器打包并验证签名。

完成后下载该次运行的 `FoLocal-macos-arm64-<commit>` Artifact，内含 DMG、ZIP、源码提交标识和 SHA-256 校验文件，保存 30 天；需要长期保存时下载到本机。也可使用 `gh workflow run folocal-check.yml --repo Zonezzc/FoLocal --ref dev -f package=true` 触发。

打包不创建 PR，不自动发布 Release，也不安装到本机。安装包采用 ad-hoc 签名，未经过 Apple 公证。个人数据库及 AI 配置留在本机，不上传到 GitHub。

## 发布前验证

### 本地可靠性

- 自动刷新按每个源的下次尝试时间排队，每 30 秒检查到期任务，最多同时请求 3 个源；不会在第 200 个源截断。刷新中的新选择会加入同一队列。
- 临时请求失败按 5、10、20 分钟等间隔延迟重试，上限 24 小时；404/410 每天重试，解析失败每 6 小时重试。设备断网不累计失败次数，恢复后每轮最多重试 3 个已标记离线的源。订阅健康页支持错误分类、最近成功时间、单独重试和暂停自动刷新。
- 刷新历史保留最近 50 个批次，界面展示最近 5 个批次的尝试、失败、延后数量与耗时；最近批次成功不等于全部订阅正常。
- 1.13.2 修复中文发布日期解析、重复刷新覆盖旧文章时间和特定错误 CDATA 包装；新增响应大小限制，并保持 XML 深度保护。新版本成功刷新时，会用可解析的源日期纠正此前覆盖的文章时间。
- RSS、RSSHub 与 AI 使用 Electron 的 Chromium 网络会话，继承系统代理及应用内代理规则；命令行服务继续使用原生 fetch。
- 完整备份保存数据库、AI 配置、桌面设置、Local Storage 和 IndexedDB 等阅读数据，排除浏览器缓存、日志及系统凭据。API 密钥包含在本地备份中，备份目录权限为仅本人访问。
- 备份与恢复通过重启后、打开数据库与界面存储前执行，目录为数据目录旁的 `FoLocal-backups`。恢复前检查文件哈希、数据库完整性与外键，并自动保存恢复前的快照。中断的恢复在下次启动时先回退；损坏或来自更高数据库版本的备份会被拒绝。
- 应用版本升级前自动保存快照。发布新构建必须递增应用版本号；不要在不同程序版本间复用同一版本号。当前数据库版本为 1，旧版本 0 自动升级。

### 验证顺序

1. 构建主进程声明，再依次完成类型检查、lint 和测试。
2. 构建 Electron，检查应用标识和链接协议。
3. 用 `FOLO_E2E_USER_DATA_DIR` 指定临时目录，验证全新启动、订阅抓取、摘要和翻译。
4. 使用临时目录的数据副本测试覆盖升级，确认文章、已读、收藏和设置保留。
5. 发布我们自己的版本，保留前一版本和数据备份。未配置 Apple Developer 签名时只能提供 ad-hoc 签名版本，不能宣称已经公证。
